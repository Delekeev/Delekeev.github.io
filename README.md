# Конвейер задач — интерактивный прототип

**Живая демка:** <https://delekeev.github.io/conveyor-proto/>

## Что это

Кликабельный прототип интерфейса «конвейера задач» — сервиса, в котором
ИИ-агенты параллельно делают задачи с доски, а человек ставит задачи и принимает
результат. Вдохновлён «Конвейером тасков ПРО» (html5-studio.ru) и подходом
Graphify (граф знаний по кодовой базе). Данные в демке — вымышленные, домен
взят из реального монорепозитория (NestJS + React, платформа пребординга).

Это **визуальный макет**: всё работает на локальном состоянии браузера,
никакие настоящие задачи, репозитории и доски не затрагиваются.

## Что можно потыкать в демке

- **Доска**: Бэклог → В работе → Ревью → Доработка → В мастере. Карточки
  открываются, задачи двигаются кнопками.
- **Карточка задачи**: ход агента в реальном времени, отчёт агента, отчёты
  двух ревьюеров (код + архитектура), кнопки «В мастер» / «На доработку».
- **Арбитр** (панель слева): главный ИИ проекта. Журнал пробуждений,
  кнопка «Разбудить», «уроки проекта», которые копятся от задачи к задаче.
- **Эпики волнами** (панель справа): большая фича делится на волны подзадач,
  волны идут параллельно и принимаются целиком.
- **Режимы автоматики**: Ручной / Полуавтомат / Автопилот и красный
  **стоп-кран**, который гасит всю автоматику одним нажатием.
- **Отчёт спринта**: что сделано, что в работе, что осталось, что нужно
  от владельца продукта.

## Как это запланировано в боевом виде

Прототип показывает целевую архитектуру сервиса:

```
issue с меткой conveyor:ready (GitHub Issues = доска)
   │  конвейер забирает задачу
   ▼
ветка conveyor/issue-N + отдельная рабочая копия проекта (worktree)
   │  агент (Claude Code / Codex / Kimi) делает задачу, мастер не трогается
   ▼
pull request + метка conveyor:review
   │  два AI-ревью: обычное и архитектурное (против графа знаний кодовой базы)
   ▼
чисто → мерж, issue закрыт с отчётом  /  замечания → доработка агентом
```

Ключевые решения:

1. **Доска — GitHub Issues**, статусы — метками. Jira/YouTrack подключаются
   позже тем же интерфейсом. Берутся только задачи, которые владелец явно
   пометил, — автоматика никогда не хватает чужие задачи.
2. **Изоляция**: у каждой задачи своя ветка и своя копия проекта. В мастер
   попадает только прошедшее ревью; откат — один `git revert`.
3. **Арбитр**: дежурный ИИ, который просыпается по событиям (вопрос агента,
   возврат ревью, конфликт мержа, готовность волны), решает по правилам
   проекта и засыпает. Деплой, оплата и внешние системы остаются за человеком.
4. **Граф знаний по коду** (свой аналог Graphify на tree-sitter, уже собран):
   архитектурный ревьюер смотрит, какие части системы затрагивает PR,
   а агенты спрашивают граф вместо перечитывания файлов — экономия токенов.
5. **Память проекта**: «уроки» после каждой задачи, модель под сложность
   задачи (дешёвая для мелочи, сильная для архитектуры).
6. **Режимы**: Ручной → Полуавтомат → Автопилот, стоп-кран всегда под рукой.

## Технически

- Статический сайт: React 19 + Vite + Tailwind, без бэкенда и базы.
- Собранная версия лежит в `conveyor-proto/` и раздаётся через GitHub Pages.
- Локальный запуск из исходников: `npm install && npm run dev`
  (исходники пока живут в рабочем проекте, сюда выложена сборка).

## Зачем

Показать, как может выглядеть и ощущаться собственный конвейер задач,
прежде чем вкладываться в разработку: доска, арбитр, ревью и эпики —
в одном экране, который можно потрогать руками.
